# How to geocode a place

**Geocoding turns a place name such as "Tokyo Station" into latitude and longitude; for a small app, search the place with OpenStreetMap's public Nominatim API, keep the coordinates it returns, and stay inside its usage policy.** The steps are small, but the service has strict rules, and breaking them gets the whole app blocked.

## 1. Use the public API only for small, occasional lookups

The public Nominatim search endpoint is free, needs no key, and answers a free-form query with coordinates. The OpenStreetMap Foundation publishes a [usage policy](https://operations.osmfoundation.org/policies/nominatim/) for it, and the limits are the hard part:

- **No bulk or heavy use.** The policy says: "No heavy uses (an absolute maximum of 1 request per second)." The limit is for the whole app, not per visitor.
- **Identify the application.** Requests must "Provide a valid HTTP Referer or User-Agent identifying the application", and "(stock User-Agents as set by http libraries will not do)."
- **Cache, and stay switchable.** The policy asks apps to use a proxy where feasible, cache results, and be able to change providers on request without shipping an update.
- **Attribution.** The map data is under the Open Database License (ODbL), and the app must credit OpenStreetMap ([OpenStreetMap copyright](https://www.openstreetmap.org/copyright), checked 2026-11-27).

The policy also rules out autocomplete, systematic or grid queries, bulk downloads, and reselling results, and says a service whose main purpose is geocoding must run its own. It adds that code generated by a large language model must follow the policy too. For a small app adding a few dozen places, the public endpoint fits; for autocomplete, thousands of rows, or map-heavy products, self-host Nominatim or use a paid provider instead.

## 2. Make one identified request

The [search API](https://nominatim.org/release-docs/latest/api/Search/) takes `q`, `format`, `limit` and `accept-language` as query parameters. `format` defaults to `jsonv2`, `limit` defaults to 10 and cannot be more than 40, and JSON results give `lat` and `lon` as strings, so convert them to numbers.

```js
const UA = "MyTripBoard/1.0 (https://example.com)";

async function geocode(query) {
  const params = new URLSearchParams({
    q: query,
    format: "jsonv2",
    limit: "1",
    "accept-language": "en"
  });
  const response = await fetch(`https://nominatim.openstreetmap.org/search?${params}`, {
    headers: { "user-agent": UA, accept: "application/json" },
    signal: AbortSignal.timeout(8000)
  });
  if (!response.ok) return null;
  const [hit] = await response.json();
  if (!hit) return null;
  return { lat: Number(hit.lat), lon: Number(hit.lon) };
}
```

Use a real application name and a URL a human can check in the `User-Agent`; that is what the policy means by identifying the application.

## 3. Space the calls yourself

One request a second is easy to break when several visitors act at once, because the limit is shared by the app. Serialize geocoding behind a small queue, or, if lookups happen only when someone saves a place, keep a timestamp and wait out the gap before the next request:

```js
let lastCall = 0;

async function geocodeSpaced(query) {
  const wait = Math.max(0, 1100 - (Date.now() - lastCall));
  if (wait) await new Promise((resolve) => setTimeout(resolve, wait));
  lastCall = Date.now();
  return geocode(query);
}
```

This is also why geocoding belongs on the server: one process can hold one timestamp and one cache, while every browser would otherwise send its own requests.

## 4. Store the coordinate, not the service

Save the latitude and longitude with the place in your database the first time someone adds it. Don't geocode the same row again on every page view — repeated identical queries are exactly the traffic the policy warns about.

Keep a place usable when the lookup fails:

- Save the place without a pin, and show a "search this on a map" link instead of a broken map.
- Treat the pin as approximate. A name can match several places; ask for more results (up to 40) and let the person choose when it matters.
- Keep the provider behind one function, so switching services later is a code change in one place, not a schema change.

## 5. Show the attribution

When the pin or the map comes from OpenStreetMap data, credit the data and name the licence. The foundation's [attribution guidelines](https://osmfoundation.org/wiki/Licence/Attribution_Guidelines) accept the credit "OpenStreetMap", the older forms "© OpenStreetMap contributors" and "© OpenStreetMap", and linking the credit to `openstreetmap.org/copyright` is an acceptable way to make clear that the data is available under the Open Database License.

If you draw map tiles from a tile service, that service has its own attribution rules as well; show its required line next to the map.

## 6. Know when the public API is the wrong tool

The public endpoint is a courtesy service for light use. Move off it when any of these is true:

- You need suggestions while someone types (autocomplete is explicitly excluded).
- You are geocoding a list, a grid, or a whole city.
- Map search is the product, not a feature of it.
- You cannot keep the app under one request a second.

In those cases, run Nominatim yourself — its installation docs list a Docker setup as community guidance they "haven't tested" and "can't offer support" for — or use a commercial geocoding API with a key. Keep the rest of the app working the same way: one provider function, cached results, and a visible credit.
